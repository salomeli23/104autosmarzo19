<analysis>**original_problem_statement:**
El usuario solicitó diseñar y desarrollar una aplicación web para la gestión de servicios técnicos automotrices. El flujo de la aplicación ha sido redefinido en detalle por el usuario, estableciendo un proceso estricto por estados, roles y evidencias digitales.

**PRODUCT REQUIREMENTS (LATEST UPDATE - User Message #64):**
El flujo del sistema es el siguiente:
1.  **Creación de Cita (Estado: Agendado):** Al crear una cita, se debe generar y mostrar en pantalla un código QR y un código de cita únicos para el check-in.
2.  **Ingreso / Check-in (Sesión Asesor):** El asesor escanea el QR/código. Puede ofrecer servicios adicionales (upsell) y modificar el valor negociado. El cliente debe aprobar la orden con **firma digital, número de cédula y una foto del cliente**. Una vez aprobado, el estado cambia.
3.  **Revisión 360:** Se realiza una inspección del vehículo, capturando **fotos y video** como evidencia.
4.  **Asignación (Sesión Coordinador):** El coordinador visualiza vehículos ingresados, los asigna a técnicos y define un tiempo estimado (timer). También debe tener una opción de **Desistimiento de Servicio** para cancelar la orden si el cliente lo decide.
5.  **En Proceso (Sesión Técnico):** El técnico visualiza sus servicios, registra avances, reporta observaciones y notifica la finalización.
6.  **Facturación y Entrega (Sesión Facturación):** El rol de facturación gestiona el pago. Los estados finales son Terminado y Falta de Pago y **Facturado y Entregado**. La entrega final requiere una **foto de evidencia**.
7.  **Alertas:** Se requieren notificaciones internas (push) para los distintos roles sobre asignaciones, retrasos, etc.
